# SPAM 汉化技术方案（用户选择已收敛）

调查日期：2026-10-15，Asia/Shanghai。对应本机 Steam build 25941248，安装目录 `E:\SteamLibrary\steamapps\common\SPAM`。本文已纳入用户对 Q1–Q9 的回答，先汇总整体方案，再进入客户端小样。当前尚未制作或安装补丁，也没有启动游戏测试。

## 用户已确定的目标

- 第一版完整覆盖玩法与常用界面：卡牌、技能、状态、天赋、教程、常用菜单；背景故事和图片文字后续补齐。
- 用于自己，也可能免费分享给朋友；译文独立维护，安装与恢复要方便。
- 用户知悉官方修改政策尚未明确允许汉化，选择在方案确定后先做可回滚的本地客户端试验。
- 技术路线确定为专用插件，暂时借用 English/en 设置。
- 默认显示中文；按住一个可配置快捷键临时显示最新英文原文，松开回到中文。名称旁不要求常驻英文。
- 随补丁发布验收译文；未译或原文变化的内容可后台自动初翻，草稿用不同字体。
- 自动初翻默认尝试免密钥接口，失败保留英文；完成且结构检查通过后自动刷新当前界面。
- 用户明确选择只用字体区分译文状态，不加“机译”标记或悬停提示。

## 已确认的技术事实

本地程序和资源的只读调查确认以下内容。进一步证据见 `analysis-local` 下的调查报告、解析摘要与程序分析文件。

1. 游戏采用 Unity **6000.3.10f1**、Mono 后端，并使用 TextMeshPro 显示文字。`SPAM_Data\Managed\Assembly-CSharp.dll` 中可以辨认现有语言管理系统。
2. 主要文字已经有固定编号（key），不是都写死在图片上。例如卡名用 `Card.Name.*`，教程消息接收文字编号后再在客户端翻译。可见 `Assets.SimpleLocalization.Scripts.LocalizationManager`、`LocalizationSettings`、`Spam.Data.CardData`。
3. `LocalizationSettings` 通过 `Resources.Load` 获取内嵌资源，`Read()` 读取各张表的 `TextAsset.text`。本次未见把任意 CSV 放进安装目录就能读取的外置语言包入口。
4. 在 `resources.assets` 提取到 **24 份 CSV、4,403 个唯一文字 key**。其中卡名 266 条、技能名 492 条、技能及被动说明 585 条、关键词 80 条、天赋 194 条、教程 176 条、Label 1,359 条、Game 53 条。条目数量不等于实际开放卡牌数量，全部文字总量也不等于首版范围。
5. 检查到的 **5 份 TMP 字体字符表均没有 CJK 汉字**。主要字体使用静态字形图集，直接替换译文会有缺字问题，因此需提供中文字体资源。
6. 解析到的 3,620 个 TMP 文字对象里，1,138 个启用自动字号。这个计数涵盖资源和界面对象，不等于屏幕同时显示的文字数；说明不能假定自动缩字能解决全部排版。
7. 585 条技能说明中，472 条有尖括号变量或排版标记，387 条有方括号 token；两类可以重叠。`<value1D>`、`<min1D>`、`<max1D>` 等参与实际数值和颜色生成，`[FEU]` 等参与元素图标生成。翻译必须保留标记和引用关系。
8. 卡牌搜索用 `AllEntries()` 收集不同语言的名称并缓存。只改屏幕最终文字不足以保证中文搜卡。译文应在首次建立搜索索引前可用，并保留原英文搜索能力。
9. 公告和商店请求使用语言代码。新增真正的中文语言项可能把服务端请求变成 `lang=zh`；服务端是否接受未知。首版沿用 English/en，只在本机显示层接入中文，可减少这个额外兼容变量。
10. 对已审查的卡牌网络序列化路径，传输的是卡牌 ID、样式、天赋与状态，未传本地译出的卡名；聊天发送用户输入内容。这支持把改动限制于显示层，但不证明所有联网路径都不受影响。
11. 已找到例外：`Label.NewDeck` 被用于新建牌组的默认 Name，牌组名称会进入账户/网络数据。该 key 宜保留原文，只汉化相关按钮或显示标签，避免将默认中文名写到账户。另有服务器直接提供的匹配提示文字，不能假定所有可见内容都在 CSV 中。

## 方案比较

| 方式 | 通俗原理 | 对体验和维护的具体影响 | 当前判断 |
| --- | --- | --- | --- |
| 官方语言包接入 | 官方提供入口，把译表交给游戏读取 | 官方能统一字体、语言选择、联机和更新兼容；取决于开发者是否愿意提供入口 | 目前未找到可确认入口或汉化授权 |
| 专用汉化插件 | 启动时加载一个小插件，按文字编号提供本地译文，配中文字体 | 可控制数值标记、搜索、英文对照、布局和回退；有加载器与游戏版本兼容成本 | 技术上最适合首版试验 |
| 直接替换资源 | 把资源包中的语言表和字体改成中文 | 启动时少一层插件；但游戏更新或文件验证可能覆盖补丁，旧资源也容易带入过期内容，恢复与适配更费事 | 不作为默认推荐 |
| 通用屏幕文字替换 | 文字显示时按整句英文查中文 | 上手快，能用预制离线译文；但上下文、动态数字、图标、中文搜卡和布局需额外处理 | 可用于采集漏译，不作为主要实现 |
| 游玩时在线机翻 | 对尚无有效译文的文字请求翻译服务 | 首次有等待，接口可能失效，规则和术语可能误译 | 用户选择作为后备层，保持草稿状态并用不同字体 |

BepInEx 是可用于 Unity Mono 的插件框架，不能由其通用支持直接推出本游戏已兼容；具体版本需通过原型确认。[BepInEx 官方源码与说明](https://github.com/BepInEx/BepInEx)

XUnity.AutoTranslator 支持预制手工译文、文本替换和 TMP 字体设置，并非只能在线机翻。因此上表把“通用文本替换”和“在线机翻”分开。其文档也提示资源直接覆盖的版本适配问题和正则过多的性能问题。[项目官方文档](https://github.com/bbepis/XUnity.AutoTranslator)

## 推荐首版结构

首版采用 **小型专用 BepInEx 插件 + 按 key 的验收译文表 + 独立机译缓存 + 两套中文 TMP 字体 + 按住切换原文 + 必要的局部显示修正**，暂时沿用 English/en。用户已选择这条路线，加载器与显示兼容性尚未经过启动验证。

### 译文状态与发布

| 状态 | 使用条件 | 显示方式 | 保存位置 |
| --- | --- | --- | --- |
| 已验收 | key、当前英文原文校验值与条目匹配，译文通过约定验收 | 正常中文字体 | 随补丁发布的验收表 |
| 机译草稿 | 没有有效验收译文，当前原文的初翻通过结构检查 | 不同的中文字体 | 玩家本机独立草稿缓存 |
| 待翻译／初翻失败 | 无译文、接口不可用或标记检查失败 | 当前英文原文 | 待处理队列／失败记录 |

已生成译文不能自动算已验收。首版译文经过术语、规则、格式和显示核对后写入验收表。后续审定草稿，只升级对应原文版本的条目；新补丁的验收表优先于本地草稿，其他草稿保留原状态。

每条记录至少保留 key／来源上下文、英文原文校验值、中文和状态；草稿另记翻译服务与时间。仅 key 相同不足以证明仍适用：官方改说明而保留 key 时，旧验收译文失效，当前原文进入初翻流程。

未译英文也可能是首次漏译或服务器临时文字，不能据此直接宣布游戏更新。版本变化由 Steam build 与程序兼容检查判断，译文适用性由原文比对判断。

### 按住快捷键查看原文

建议默认 **F8**，支持配置改键，按键冲突需小样确认。

- 松开状态：显示匹配当前原文的验收中文、草稿中文或英文。
- 按住状态：本补丁管理的游戏文字显示当前英文原文，包括名称、说明、教程、菜单与提示；保留原版图标、颜色与当下数值。
- 松开立即恢复对应中文；按住期间新开的界面也显示英文。后台初翻可写入缓存，但不把当前画面改回中文。
- 切换只改变本机显示，English/en 代码、账户、网络数据和搜卡索引不跟随按键翻转；中文和英文搜索始终可用。
- 游戏失去焦点时复位按住状态，避免在其他窗口释放按键后卡在英文。

不能只改字典加一次 `ForceLocalizationChanged()`。部分教程、关键词提示、历史详情和通知缓存了已格式化字符串或未订阅语言事件，需绑定文字 key／来源、参数／实时对象与刷新回调。关键词以 Language 为键的缓存切换时要更新；搜卡双语索引独立于临时显示语言。

保留来源不等于保存旧屏幕快照。技能刷新应重新调用当前对象的动态描述方法，按住原文时仍显示当前伤害，松开后中文也用当前数值；历史界面则使用对应历史条目的数值。只更新已绑定组件，不逐帧扫描全游戏。详细证据见 `analysis-local\原文切换与译文状态.md`。

### 自动初翻的等待与失败

仅对识别为游戏自身内容且缺少有效译文的文本初翻；动态数值、账户资料、玩家名称、聊天输入和已知会写入账户的默认牌组名不作为通用翻译对象。首版默认免密钥接口，具体服务在目标环境测试后选定，并允许更换。免密钥不等于稳定，XUnity 对 Google/Bing 相关端点明确标注可能失效。[官方端点说明](https://github.com/bbepis/XUnity.AutoTranslator#translators)

处理顺序：匹配的验收表 → 匹配的草稿缓存 → 先显示英文并加入后台队列 → 收到完整结果且标记检查通过 → 自动刷新仍显示同一来源的组件。相同来源与原文合并请求，结果保存磁盘，重开游戏不重复请求已缓存内容；超时失败退避，操作和对局不等待翻译。

先保护数值占位符、元素 token、颜色、链接及控制标签，返回后检查并恢复。标记损坏或恢复失败就保留英文，不能显示可能错配数字或丢图标的结果。结构检查只证明格式完整，不能证明规则、触发条件和术语准确；机译仍用草稿字体。

用户选择完成后自动更新当前界面，首次文字可能从英文变中文一次，换行与字体可能变化。异步返回须核对组件仍存在、仍绑定同一原文，并重新读取当前参数，避免上一张卡的结果覆盖下一张卡。按住原文时等待松开再显示中文。

初翻失败不影响已有验收中文。程序接口不兼容或中文字体无法可靠加载时，仍应停用对应功能或整包汉化；自动初翻不能修复加载器或程序接口变化。

备选接口与凭据要求见同目录 `自动初翻接口调研.md`。公开补丁不包含私人 API 密钥。

### 译文与实时数值

验收译文在游玩前准备，运行时优先本地查表；未覆盖内容才进入后台初翻。例如概念模板“造成 `{0}` 点伤害”中的数字继续由游戏填入；SPAM 实际使用的许多标记形如 `<value1D>`，应逐项确认并原样保留。不要把某次屏幕上看到的伤害数字写死进翻译。

导出时同时记录 key、原文和原文校验值。检查占位符、颜色、链接、图标及控制标签是否在译文里完整保留。术语须统一区分造成伤害、失去生命、治疗、护盾、冷却以及触发条件。数字正确仍不足以代表规则翻译正确，条件语句也要核对。

### 字体与布局

随补丁提供中文字体，避免要求朋友自行安装系统字体。优先采用合法可分发的中文字体，如思源黑体，并附其许可。[字体官方项目](https://github.com/adobe-fonts/source-han-sans)、[字体许可](https://github.com/adobe-fonts/source-han-sans/blob/master/LICENSE.txt)

首版字体候选为验收中文使用思源黑体，机译草稿使用思源宋体，具体字重和小字号可读性通过样稿验证；按用户选择只以字体区分，不增加标记或悬停提示。[思源宋体官方项目](https://github.com/adobe-fonts/source-han-serif)

字体状态由文本来源绑定决定，不能把两种字体塞进同一个全局后备链后期待系统自动识别验收状态。单个显示字段混合验收与草稿片段时，首版可保守让含草稿的整个字段使用草稿字体，条目记录仍保持精确状态；逐片段换字体只有在图标、链接及材质兼容验证后采用。

TMP 可以在原字体缺字时查找后备字体，适合补足汉字，同时保留原来的数字、拉丁字母和图标风格。[Unity TMP 后备字体说明](https://docs.unity3d.com/Packages/com.unity.textmeshpro@4.0/manual/FontAssetsFallback.html)

已知译文用预先生成的字形；需要动态补字时保留相应字体源，具体资源方式需实测。字体会增加下载体积和内存用量，不能在尚未制作字体包时给出可信的 MB 或帧率数字。

自动初翻可能产生初版词库未出现过的汉字，不能只生成已验收词库的小字库。两套字体需有足够覆盖或动态补字后备；动态补字保留字体源且有额外计算和体积成本，优先预热常用字，资源上限与首次补字卡顿需实测。[Unity 动态字体说明](https://docs.unity3d.com/Packages/com.unity.textmeshpro@4.0/manual/FontAssetsDynamicFonts.html)

优先修正长技能说明、关键词提示、教程气泡和窄按钮。只缩小全部文字容易变得难读，应先缩短措辞、允许合理换行，必要时局部调节字号或容器。保留可点击的关键词、颜色与元素图标。

本地程序还显示两个需专门验证的中文问题：

- `AbilityData.ReplaceElementLogo` 的匹配规则把中文也当作字母。中文紧贴 `[FEU]` 等元素标记时，显示解析可能把前面的词句一起吞掉。应使用兼容的标点/标记格式，或在显示处理处做最小修正，并检查转换结果。
- `KeywordHighlighter` 采用拉丁语系的词边界和大写判断，中文句子里的关键词可能无法高亮和显示悬停解释。优先确认原生显式 marker/citation 格式能否稳定保留提示，必要时对中文边界作显示适配。

这两个问题说明字体和译表都正确，也不代表游戏体验已完成；验收必须包含实际图标和关键词交互。它们与战斗计算是不同路径，适配应限于显示。

### 搜索、名称与语言代码

让中文名称进入搜卡索引，并保留英文搜索，方便对照攻略。索引有缓存，因此加载时机和重建时机须验证；搜卡输入框是否正确处理中文输入法也要实测。

首版客户端底层仍使用 English/en，中文只进入本机译文显示层，游戏设置暂时选 English。实现应保留一份原英语表，供原文对照和回退，避免仅覆盖译文后丢失英文名称。

后续若新增 Chinese 语言项，除注册语言字典外还需同步 LocaleNames，并审查所有语言枚举与语言代码发送位置。已存在的 `EachLanguages` 对字典语言查找 LocaleNames，没有正确登记可能出错；当前分析未发现它在本程序集内被调用，这不代表未来版本不会用。

### 更新、安装和恢复

译表与插件分开发布；翻译改动无需总是更换插件。安装器或安装说明应明确文件清单与适用 build，卸载只删除补丁自己的文件，并提供英语恢复方式。更新前后比对游戏原文，避免使用旧说明。

确定策略：变化条目先显示最新英文，后台生成草稿，通过标记检查后以草稿字体自动显示；接口或字体兼容性验证失败时关闭对应功能或整包停用。原文校验能发现文字变化，不能覆盖所有逻辑、数据和布局变化，仍需版本适配与抽样核验。

## 客户端试验的验收重点

先完成一小组能覆盖主要问题的样本：常用菜单、一张长描述卡牌、实时数值变化、一个带图标及关键词链接的技能、一段教程、中文和英文搜卡。确认这些后再扩大翻译范围。

- 能正常从 Steam 启动；补丁加载成功，恢复英语后同样可用。
- 中文字体完整，长文本没有裁切、重叠或小到难读，关键词提示仍可交互。
- 技能数值、图标、颜色和触发条件与原版一致，翻译不改变卡牌 ID、存档格式和对战逻辑。
- 搜卡输入法可用，中文和英文名称都能找到正确对象。
- 按住和松开快捷键能刷新已打开的卡牌、动态说明、教程、关键词提示、历史和通知，数值及历史语境正确；按住期间新窗口仍为英文、初翻返回不覆盖英文，失焦后不残留模式。
- 验收条目与草稿采用两套字体，不出现额外标记或提示；机译的新增汉字也完整显示。含草稿的合成字段不能呈现成全条已验收。
- 模拟新 key、原 key 改原文、损坏 token、翻译超时，以及看完上一张卡后才收到结果：确认验收状态失效、草稿缓存匹配、失败回退和界面不串卡；已有验收中文不依赖初翻接口。
- 原版与汉化版在相同场景比较启动耗时、内存和帧率；目前未测量，不能承诺无额外开销。
- 核对登录、菜单、教程和连接兼容；真实对战和联机表现只能在后续客户端试验中确认。

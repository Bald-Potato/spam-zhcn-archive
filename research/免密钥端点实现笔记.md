# 免密钥端点实现笔记

日期：2026-10-15（Asia/Shanghai）。核对 XUnity.AutoTranslator 当前 master，固定提交 `08324a58dcb26b76fc08e0fb2121098164579e73`。只读研究；仅向 Bing 发送一次公开单词 `Play`，未发送游戏文本、未测试批量、未注册或调用收费 API。

## 可直接实现的 Bing 请求

1. **XUnity 代码与现行网页存在差异。** XUnity 的 BingTranslate 先 GET `https://www.bing.com/translator`，同 CookieContainer 提取 `IG:"..."` 与 `data-iid="..."`；随后 POST `/ttranslatev3?isVertical=1&IG={IG}&IID={IID}.{序号}`。源码表单只有 `fromLang`、`text`、`to`，**没有提取或发送 key/token**。[固定版本源码](https://github.com/bbepis/XUnity.AutoTranslator/blob/08324a58dcb26b76fc08e0fb2121098164579e73/src/Translators/BingTranslate/BingTranslateEndpoint.cs)

2. **本次正常 Bing 官方网页还含动态 key/token。** 页面有 `params_AbusePreventionHelper = [数字key,"token",第三项数值]`；与 IG、IID 一起从正常页面读取，勿硬编码其值。可用匹配形状 `params_AbusePreventionHelper\s*=\s*\[\s*([0-9]+)\s*,\s*"([^"]+)"\s*,\s*([0-9]+)\s*\]`。提取失败、返回验证码或挑战时暂停该服务，不猜值、不绕挑战。第三项含义未额外核实，本笔记不将其作为稳定契约。[实际读取的官方网页](https://www.bing.com/translator)

3. **一次成功的请求形状：** GET 页面时建立 Cookie 会话，POST 复用同会话；使用以下参数及请求头。HTTP 200 返回 `[{"translations":[{"text":"玩","to":"zh-Hans",...}],...}]`，取 `[0].translations[0].text`，仅接受成功 JSON、非空译文与预期目标语言。本次这一个成功样本不能证明各参数都为服务端强制要求，也不能证明批量或未来稳定。[官方网页](https://www.bing.com/translator)、[XUnity 参数及解析参考](https://github.com/bbepis/XUnity.AutoTranslator/blob/08324a58dcb26b76fc08e0fb2121098164579e73/src/Translators/BingTranslate/BingTranslateEndpoint.cs)

```text
POST https://www.bing.com/ttranslatev3?isVertical=1&IG={IG}&IID={IID}.1
Content-Type: application/x-www-form-urlencoded
Accept: */*
Origin: https://www.bing.com
Referer: https://www.bing.com/translator
Cookie: 由同一 HttpClientHandler/CookieContainer 自动维护

fromLang=en
text=Play
to=zh-Hans
key={本次正常页面给出的数字}
token={本次正常页面给出的字符串}
```

用 `FormUrlEncodedContent` 编码表单，避免自己拼接漏转义；`zh`/`zh-CN` 转为 `zh-Hans`。XUnity 设置固定的 User-Agent、Accept/Origin/Referer/Content-Type，Accept-Language 可选。本次 PowerShell 没有显式设置浏览器 User-Agent 也成功；HttpClient 实现仍应在页面与 POST 保持一致的正常会话设置。XUnity 有关闭证书检查的旧兼容逻辑，专用 HttpClient 保持正常 TLS 校验。

## GoogleTranslateV2 的源码形状（本次不再请求 Google）

4. **V2 是 Google 网页 RPC，并非另一个独立提供商。** 默认后端 `https://translate.google.com`，POST `/_/TranslateWebserverUi/data/batchexecute`；RPC ID 默认 `MkEWBc`。先 GET 首页并复用 Cookie，从 `FdrFJe":"{值}"` 提取 `f.sid`。源码的 `bl` 默认仍是 `boq_translate-webserver_20210323.10_p0`；首页取不到 FSID 时源码会用随机值，但这不是有效会话的保证。源码没有 `at` 或用户 API 密钥，不应因为默认配置仍存在就保证现行可用。[固定版本 Google V2 源码](https://github.com/bbepis/XUnity.AutoTranslator/blob/08324a58dcb26b76fc08e0fb2121098164579e73/src/Translators/GoogleTranslate/GoogleTranslateEndpointV2.cs)

5. **请求不是普通翻译 JSON。** 查询参数有 `rpcids`、`f.sid`、`bl`、`hl=en-US`、`soc-app=1`、`soc-platform=1`、`soc-device=1`、`_reqid`、`rt=c`。正文是 form 字段 `f.req`，值为外层 JSON，而里面又嵌一段 JSON 字符串：

```text
inner = JSON serialize([["Play","en","zh-CN",true],[null]])
outer = JSON serialize([[["MkEWBc", inner, null, "generic"]]])
body = FormUrlEncodedContent({"f.req": outer})
```

源码头包括 `Referer: {backend}/`、`Origin: {backend}`、`X-Same-Domain: 1`、`DNT: 1`、`Accept: */*`、`Content-Type: application/x-www-form-urlencoded;charset=UTF-8` 与 User-Agent；网页 GET 另加 `Upgrade-Insecure-Requests: 1`。响应有前缀和长度分块，内部再有 JSON 字符串；不能按普通 JSON 数组直接解析。源码依靠固定数组位置提取翻译，遇到结构变化应报告解析失败，不能把整段错误页缓存为译文。[固定版本 Google V2 源码](https://github.com/bbepis/XUnity.AutoTranslator/blob/08324a58dcb26b76fc08e0fb2121098164579e73/src/Translators/GoogleTranslate/GoogleTranslateEndpointV2.cs)

## 限流、回退与当前结论

6. **XUnity 现有停机逻辑不是完整的 429 退避。** 核对的两份端点源码及 `TranslationEndpointManager` 未见专门读取 `Retry-After` 的逻辑；管理器按通用失败处理，可配置 fallback，同一文本单端点失败阈值为 3，连续错误阈值为 5，批量失败会暂停批量 60 秒。上述是 XUnity 行为，不是翻译服务承诺。[管理器](https://github.com/bbepis/XUnity.AutoTranslator/blob/08324a58dcb26b76fc08e0fb2121098164579e73/src/XUnity.AutoTranslator.Plugin.Core/Endpoints/TranslationEndpointManager.cs)、[阈值配置](https://github.com/bbepis/XUnity.AutoTranslator/blob/08324a58dcb26b76fc08e0fb2121098164579e73/src/XUnity.AutoTranslator.Plugin.Core/Configuration/Settings.cs)

7. **专用插件建议：** 单并发、磁盘缓存、重复文本去重；HTTP 429 立即暂停该提供商，若有 `Retry-After` 尊重其秒数/日期，否则设明确冷却并让用户手动恢复或切换。不要把同一家 Google 的 V1/V2 当成不断重试通道；两者共享提供商冷却。独立可选 Bing 本次单句可用，选择后仍应限速，不开始批量扫描。失败保留英文与已缓存译文，日志只写服务/状态/错误类别，不记录 token 或 Cookie。以上是建议，未作压力测试。

8. **结论：** 可以实现可选 Bing 适配器，但应采用正常网页提供的 key/token 加同 Cookie 会话；照抄 XUnity 的无 key/token 旧 Bing 表单缺乏当前成功证据。Google V2 可作为兼容选项研究，不适合作为已收到 429 后立即切换并继续打同服务的办法。两种免密钥实现都不是供应商正式保证的开发者 API。[XUnity 稳定性说明](https://github.com/bbepis/XUnity.AutoTranslator#translators)

## PowerShell 与 Python 401 差异复核

2026-10-15 05:25:37（Asia/Shanghai）只再探测公开单词 `Play` 一次，PowerShell GET、POST 均 HTTP 200，译文仍为“玩”；Python urllib 的 401 为主任务报告，本辅助任务未再用 Python 发送翻译请求。[可复现单句脚本](../scripts/check-bing.ps1)

- 实际工具运行在 PowerShell **7.6.5 Core**。成功请求没有设置 `-UserAgent`；WebSession 实际默认值为 `Mozilla/5.0 (Windows NT 10.0; Microsoft Windows 10.0.26200; zh-CN) PowerShell/7.6.5`，不是 Chrome 字符串。GET 与 POST 共用该 WebSession。
- `IG:"([^"]+)"` 匹配 1 个，`data-iid="([^"]+)"` 匹配 3 个，成功请求确实用各自的**首个**匹配，IID 后加 `.1`；没有挑另一处 IID。
- key/token 来自同次 GET 的 `params_AbusePreventionHelper`，直接使用正则原始捕获；**未做 JSON、HTML 或 URL 解码**。此次 token 不含反斜杠，所以 JSON 字符串反转义的差异没有本次支持证据。
- 同一 WebSession 保存的 Cookie 数量为 9；本笔记及脚本不输出其名称或内容，也不复用早先会话。
- GET 的 `Cache-Control` 为 `private`，`Age` 未出现，服务器 `Date` 比本机记录的请求开始时间晚约 1 秒；本次没有明显陈旧页面证据。它不能完全排除中间网络设备缓存。
- 目前**不能确定 401 是 User-Agent、Cookie 行为、系统代理路由还是其它客户端差异**。此脚本证明这一 PowerShell 请求形状在当次网络可用；没有读取代理凭据、改变代理、处理挑战或绕过鉴权。
